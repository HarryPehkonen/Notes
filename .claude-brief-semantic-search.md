# TDD Brief: Semantic Search Toggle (Variant A — exclusive switch)

## Goal

Add an optional **semantic search mode** to the Notes app, toggled by a
labeled checkbox after the search input. Per user decision (Aug 2026):

- **Unchecked (default)** = current Postgres tsvector full-text search —
  behavior unchanged.
- **Checked** = EXCLUSIVE semantic search via local BGE-M3 embeddings +
  pgvector. No text-search results mixed in.
- Label: "Semantic search" — must be a LARGE, HIGH-CONTRAST labeled control
  (user's eyesight requirement; NOT a subtle icon toggle).
- User is the only user; no onboarding/learnability concerns beyond the
  label itself.

## Architecture

- VPS notes-server has llama.cpp serving BGE-M3 at `127.0.0.1:8080`
  (OpenAI-compatible /v1/embeddings, 1024-dim).
- Postgres 17 has pgvector extension installed.
- Search flow today: `search-bar.js` (debounced input) → `search-query`
  event → `notes-app.js` → `NotesApp.searchNotes(query, options)` →
  `GET /api/search?q=...` → `server/api/search.js` → `db.searchNotes()`
  (tsvector FTS, weighted title=A content=B, tag filter support).

## Design decisions (already made — implement as specified)

1. **API:** `GET /api/search?q=...&semantic=1` — when `semantic=1`,
   server embeds the query via `http://127.0.0.1:8080/v1/embeddings`
   (model bge-m3) and searches pgvector over the user's note embeddings.
   Response shape IDENTICAL to text search: `{success, data:{query,
   results}, meta:{total, limit, offset, hasMore}}`. Results sorted by
   similarity DESC (most similar first).
2. **Schema:** new table `note_embeddings`:
   ```sql
   CREATE TABLE IF NOT EXISTS note_embeddings (
     note_id INTEGER PRIMARY KEY REFERENCES notes(id) ON DELETE CASCADE,
     user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
     embedding vector(1024) NOT NULL,
     updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   );
   CREATE INDEX IF NOT EXISTS idx_note_embeddings_user ON note_embeddings(user_id);
   ```
   (vector column requires the pgvector extension — already installed on
   VPS. Keep schema.sql idempotent like the rest.)
3. **Backfill:** a one-time script `scripts/embed-notes.ts` (Deno) that
   reads all notes, embeds title+content_plain via the local server, upserts
   into note_embeddings. Idempotent (re-run re-embeds only changed notes by
   comparing updated_at). Embedding text format: `title\n\ncontent_plain`.
4. **Keep embeddings fresh:** on note create/update (server/api/notes.js
   POST/PUT), embed the new note content and upsert note_embeddings
   (fire-and-forget, non-blocking; log failures, never fail the note write).
5. **Frontend:** in `search-bar.js` render(), add after the input (inside
   the search-input-wrapper or a new row below it):
   ```html
   <label class="semantic-toggle">
     <input type="checkbox" class="semantic-checkbox" ?checked=${this.semanticMode} @change=${this._onSemanticToggle}>
     <span class="semantic-label">Semantic search</span>
   </label>
   ```
   - `semanticMode` property (default false).
   - `_onSemanticToggle(e)` sets `this.semanticMode = e.target.checked`,
     re-dispatches the current search with the flag.
   - Include the flag in the `search-query` event detail
     (`detail: { query, semantic: this.semanticMode }`).
   - CSS: label must be LARGE font, high contrast — dark text on light
     background, min font-size 16px, clear spacing; checkbox at least
     18x18px. Visible without hover.
6. **app.js:** `searchNotes(query, options)` — add `semantic` passthrough:
   `if (options.semantic) params.set("semantic", "1")`. NotesApp event
   handler forwards `e.detail.semantic`.
7. **Server search.js:** if `semantic=1`, skip parseSearchQuery/tag path;
   embed query, then:
   ```sql
   SELECT n.id, n.title, n.content_plain, n.updated_at,
          1 - (e.embedding <=> $1::vector) AS similarity
   FROM note_embeddings e JOIN notes n ON n.id = e.note_id
   WHERE e.user_id = $2
   ORDER BY e.embedding <=> $1::vector
   LIMIT $3 OFFSET $4
   ```
   Map results to the same shape `db.searchNotes` returns (id, title,
   content_plain/snippet, updated_at). Tag filters are NOT applied in
   semantic mode (document this in the response meta:
   `semantic: true`).
8. **Error handling:** if the embedding server is unreachable, return 502
   with `{success:false, error:"Semantic search unavailable"}` — never
   silently fall back to text search (exclusive mode semantics).

## Tests — TDD FIRST (mirror existing tests/deno conventions)

`tests/deno/` — pure functions, no network:

1. `semantic_test.ts`:
   - `parseSemanticResults(row)` — maps a pgvector row (with similarity)
     to the searchNotes result shape; test id/title/similarity mapping.
   - `buildEmbeddingPrompt(title, content)` — "title\n\ncontent" format;
     empty content → just title; trims.
   - `semanticQueryNeeds(semanticParam)` — "1"/true → semantic path;
     anything else → text path (exclusive, no hybrid).
   - Tag-flag behavior: semantic mode with `#tag` in query → tags are
     ignored (documented), test that the semantic branch is chosen.

2. Search-query pure-function tests for the frontend flag:
   - `shouldSendSemantic(checkboxState)` or equivalent pure helper in
     `public/utils/search-mode.js` — checked → true. (If the flag logic
     is trivial inline, a small pure helper keeps it testable.)

Server-side integration tests are NOT required (no live DB in tests) —
verify by running the app + curl after implementation.
